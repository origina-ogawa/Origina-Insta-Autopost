# スライドに解説キャラクターを追加する

日付: 2026-08-13

## 背景・目的

カルーセルの表紙・本文スライドに、解説役のキャラクター(人物)画像を配置する。
現状は表紙にロボットアイコン、本文スライドのタイトル横にトピックアイコン(Tabler Icons)があるだけで、
「人が説明している」印象がない。ユーザー提供の参考画像(`assets/mirai01.png` / `assets/mirai-ad.png`)の
ような、解説役の人物が右下に大きく配置されるデザインに変更する。

## 参考画像と権利関係についての記録

`assets/mirai01.png` / `assets/mirai-ad.png` はテレビスタジオのような背景で撮影されたスタイルの人物画像。
ユーザーへのヒアリングにより、**この人物はユーザー自身がAIで生成した架空の人物であり、実在の人物ではない、
権利があるとすればユーザー自身である**との説明を受けた。この設計・実装は、その説明を前提として進める。
実在の人物の肖像を無断で使う設計ではないことを、後日の確認のためにここに明記しておく。

## 全体方針

1. 上記2枚の参考画像を「同一人物・同一服装」の入力として画像生成AIに渡し、ポーズ違いの画像を
   **事前に6枚生成**して `assets/character/` にコミットする(一度だけ行う手動作業)。
2. 自動投稿の生成処理(`npm run generate` → `npm run render`)では画像生成を行わず、
   保存済みの6枚を使い回す。ポーズはスライドの順番に応じて割り当てる。
3. 表紙・本文スライドの右下にキャラクターを大きく配置する。表紙は特に大きく、本文スライドは
   チェックリスト/説明パネルに一部重なる程度の大きさ(ブラウザモックアップでユーザーが選択したB案)。

## コンポーネント設計

### 1. 画像生成スクリプト `scripts/generate-character-poses.mjs`(新規・手動実行用)

- 既存の `GEMINI_API_KEY` を使い、Gemini画像生成モデルにリクエストする。`src/generate.js` の
  `callGemini`/リトライ処理(429・5xx時に指数バックオフで再試行)と同じパターンを流用する。
- 入力: `assets/mirai01.png` と `assets/mirai-ad.png` を参考画像として渡し、「同一人物・同一服装、
  背景は白一色(#FFFFFF)、バストアップ〜半身、ポーズ違い」を指示するプロンプトを、ポーズごとに送る。
- ポーズ案(6種): お辞儀・挨拶/指さし/説明ジェスチャー(手のひらを見せる)/親指サイン/
  カードやメモを提示/腕組みで考えるポーズ
- 出力: `assets/character/pose-01.png` 〜 `pose-06.png` として保存。
- このスクリプトは日常の自動投稿フローには組み込まない。人が実行し、生成結果を目視確認してから
  コミットする。気に入らないポーズがあれば、そのポーズ番号だけ指定して個別に再生成できるようにする
  (CLI引数で対象ポーズ番号を指定可能にする)。

### 2. 設定 `config/brand.own.json` への追加

```json
"character": {
  "enabled": true,
  "dir": "assets/character",
  "poses": ["pose-01.png", "pose-02.png", "pose-03.png", "pose-04.png", "pose-05.png", "pose-06.png"]
}
```

`character.enabled` が `false`、またはこのキー自体が無いブランド設定では、従来通りアイコン表示に
フォールバックする(既存ブランドへの影響なし、後方互換)。

### 3. `src/render.js` / `src/lib/components.js` の変更

- `render.js` の `loadLogoDataUri` と同様の仕組みで、`character.poses` に列挙された画像ファイルを
  base64 データURIとして読み込む。列挙されているのにファイルが存在しない場合は、その場でエラーを
  投げて処理を止める(壊れたスライドを生成しない)。
- ポーズ割り当ては「スライドの並び順」に対する単純な連番(`poseIndex % poses.length`)。
  表紙が1枚目、以降は本文スライドの順で1つずつ進む。1投稿(カルーセル1本)の中でプール数(6)を
  超えない限り同じポーズは重複しない。
- 表紙スライド: 既存の `.cover-visual`(ロボットアイコン)をキャラクター画像に置き換える。
  右下に大きく配置(現状のロボットアイコンと同じ位置寄せ、サイズは拡大)。
- 本文スライド: 既存の `.title-visual`(タイトル横のアイコン円)を廃止し、カード右下に
  キャラクターを大きく配置する。ブラウザモックアップで承認されたB案(チェックリスト/説明パネルの
  右側に一部重なる)を採用する。パネル内のテキスト・チェック項目がキャラクターの下に隠れないよう、
  パネル右側に余白(キャラクター幅ぶん)を確保する。
- ブランド固定スライド(ロゴスライド)は対象外。変更しない。

### 4. `src/fixtures/mock-post.json` / `--mock` テストへの影響

キャラクターは `post.json` の内容とは無関係に、`render.js` がブランド設定を見て毎回付与する
純粋にテンプレート側の要素なので、`--mock` でのテストにもそのまま反映される。既存のテスト手順
(`npm run generate -- --mock` → `npm run render`)に変更はない。

## エラー処理

- `character.enabled: true` なのに `character.poses` に列挙されたファイルが `assets/character/` に
  存在しない場合、`npm run render` はエラーメッセージを出して停止する。
- 画像生成スクリプトは一時的なAPIエラー(429・5xx)を自動リトライする。それ以外のエラー
  (認証エラー・不正なレスポンス等)は即座に失敗として表示する。

## テスト方針

自動テストは追加しない。既存のテンプレート(CSS・レイアウト)も同様に、`npm run render` で生成した
PNGを目視確認する方法で検証されているため、それに合わせる。

- `npm run generate -- --mock` → `npm run render` を実行し、表紙・本文スライドでキャラクターが
  意図した位置・サイズで表示され、パネル内のテキストと重なっていないことをPNGで確認する。
- 実際のGemini生成(`npm run generate`)でも崩れないことを確認する。

## スコープ外(今回やらないこと)

- 透過PNG化(背景除去)による、白以外の背景色への対応。将来カードの配色を変える場合は
  `sharp` 等を使った背景除去の追加を別途検討する。
- 自動投稿フロー内でのキャラクター画像の都度生成(コスト・失敗リスクのため見送り)。
- 他ブランド(`config/brand.*.json`)へのキャラクター機能の展開。まずは `own` ブランドのみ。
