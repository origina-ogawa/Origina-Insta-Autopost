# 3Dオフィス表示層(viewer/) UI改修 設計メモ

作成日: 2026-08-14
関連: `docs/superpowers/specs/2026-08-13-office-viewer-design.md`(初期設計)、`viewer/README.md`、`logs/SCHEMA.md`

## 背景・目的

3Dオフィス表示層(`viewer/`)の見た目・演出に対する社長からの改善要望に対応する。
今回のスコープは以下の4点(検討順に整理し直したもの):

1. アクティビティログの文字切れ修正
2. 社員の出社/退社タイミングの見直し(常時出社→イベント発生時に出社、`done`で退社)
3. 凡例(レジェンド)パネルの削除
4. 吹き出し演出の改善(はみ出し修正+「面白いセリフ」演出の新規追加)

途中でさらに広い要望(producer表示の確認、Claude Codeの状態表示、Claude Codeへの指示入力欄)が
挙がったが、範囲を整理した結果、以下の扱いとした。

- **producer(制作)の表示**: 調査の結果、`theme.ts`の`ACTORS`一覧・実イベントログ両方に
  既に存在し、3Dビューにも表示される設計になっていることを確認した。表示ラベルは
  「制作」のままでよいと社長に確認済み。**追加対応不要。**
- **Claude Codeの状態表示・指示入力欄**: `logs/events.jsonl`を読むだけの一方向の
  仕組みである現状に対し、双方向連携が必要になり実現方式から検討が要るため、
  **今回のスコープ外。別途改めて設計する。**

## ① オーバーレイレイアウト刷新(要望1・3・6)

### 変更内容

- `LegendPanel.tsx`を削除。`Overlay.tsx`からimport・使用箇所を除去
- `panels.css`の関連クラス(`.panel--legend`, `.legend-swatches`)を削除
- `TitlePanel`は左上のまま変更なし
- `StatusPanel`(社員ステータス)と`ActivityPanel`(アクティビティログ)を統合し、
  画面**右端に縦長の独立サイドパネル**として配置する
  - 上部: 社員ステータス一覧(既存の内容のまま、コンパクトに)
  - 下部: アクティビティログ。残りの縦幅をすべて使い、スクロール可能なリストとして表示
  - 3Dシーンは左〜中央を広く使えるようになる
- `.activity-message`の`white-space: nowrap` / `text-overflow: ellipsis`を廃止し、
  折り返し表示(`white-space: normal`)に変更。サイドパネル化で確保できる横幅と合わせて、
  文字切れを解消する

### 実装への影響ファイル

- `viewer/src/ui/Overlay.tsx`(レイアウト構成の変更、LegendPanel削除)
- `viewer/src/ui/LegendPanel.tsx`(削除)
- `viewer/src/ui/panels.css`(グリッド定義の見直し、サイドパネル用スタイル追加、凡例用クラス削除、
  `.activity-message`の折り返し対応)
- `StatusPanel.tsx`/`ActivityPanel.tsx`自体のロジックは変更不要(見た目の配置のみ変更)。
  ただし2つを1つの`<aside>`的なラッパーにまとめるため、`Overlay.tsx`側の構造変更が必要

## ② 出社/退社アニメーション(要望2)

### 状態の考え方

- 各AI社員は「これまでに一度もイベントを受け取っていない」間は**アバターを表示せず、机だけ**を表示する
- 出社・退社の判定は`officeState.ts`のグローバルなreducer状態には持たせず、
  `Avatar.tsx`内でこれまでの`state.event`/`state.seq`の推移から局所的に管理する
  (既存の`scaleAnim`/`leanAnim`等と同じパターン)

### 出社(away → present)

- awayの状態で最初のイベント(種類は問わない。`start`が多いが、PMのように`handoff`から
  始まるケースもある)を受け取ったタイミングでトリガー
- 画面の外側(机の位置で決まる左右どちらか)から中央(定位置)へ歩いてくるアニメーション
  - スライド移動+軽い上下バウンスで「歩いている感」を出す(既存の控えめな動きの方針を踏襲)
  - 所要時間は目安1.2秒程度、ease-in-out(既存の`easeInOutCubic`を流用)

### 退社(present → away)

- `done`イベントを受け取ったタイミングでトリガー
- 出社時と同じ側へ歩いて画面外へ消えるアニメーション(所要時間・イージングは出社と同様)
- アニメーション完了後はアバターを非表示にし、机だけの状態に戻す
- 現状実装されている「`done`で不透明度を下げてフェードアウト」(`DONE_OPACITY`)は廃止し、
  「歩いて退出する」演出に統一する

### 退出方向のルール

- 机のワールド座標X値の符号で機械的に判定する
  - 机が中心より左(researcher, director) → 左へ出社/退社
  - 机が中心より右(inspector, publisher) → 右へ出社/退社
  - 中央寄りの机(pm, producer)は固定で右側に決め打ちする
- `theme.ts`に既存の`LEAN_TO_NEXT`/`LEAN_TO_PREV`と同様の考え方で、
  actorごとの出社/退社方向(ワールド空間のX方向)を定数として持たせる

### ページ読み込み直後の特例処理

- `logs/events.jsonl`は開いた瞬間に過去分を一括再生する仕様(既存の既知の制限、
  `viewer/README.md`参照)。このため、ページを開いた直後の最初の一括反映では
  出社/退社アニメーションを**再生しない**
  - `done`が最終状態の社員 → 最初から机だけ(出社→即退社のちらつきを防ぐ)
  - 作業中が最終状態の社員 → 最初から着席済みの状態で表示(出社アニメーションはスキップ)
- 実際にその場でイベントが届いたとき(ページ読み込み後、2回目以降の状態更新)だけ
  アニメーションを再生する
- 実装方針: Avatar内で「これが最初の状態更新かどうか」を判定するrefを持ち、
  最初の更新では位置・表示状態を直接セット(アニメーションをスキップ)し、
  2回目以降の更新でのみ出社/退社のトリガー処理を行う

### スコープ外

- 机の上の紙の蓄積(`OutputStack`)は出社/退社と連動させない(そのまま残す)
- 歩行のパスファインディング・当たり判定(既存設計メモのスコープ外方針を踏襲)

### 実装への影響ファイル

- `viewer/src/scene/Avatar.tsx`(出社/退社アニメーションの追加、`DONE_OPACITY`フェードアウトの置き換え)
- `viewer/src/scene/Office.tsx`(away状態のアバターを描画しない/非表示にする制御)
- `viewer/src/theme.ts`(actorごとの出社/退社方向の定数を追加)

## ③ 吹き出し演出の改善(要望4)

### はみ出し修正(幅・高さの自動調整)

- 現状、吹き出しの板(`planeGeometry`)は`[1.6, 0.5]`の固定サイズで、
  テキスト量が多いとはみ出てしまう
- メッセージの文字数から板の幅・高さを動的計算する方式に変更する
  - 短いメッセージはコンパクトな板に、長いメッセージは折り返し行数に応じて板を拡大する
  - 実際のイベントメッセージ・新設の「面白いセリフ」の両方に同じサイズ計算ロジックを適用する

### 「面白いセリフ」演出(新規)

- `viewer/src/data/flavorLines.ts`を新設し、役職(actor)ごとに小ネタのセリフを6〜8個程度用意する
  - 業務あるある系の軽いユーモアで、役職の性格に合わせる
    (例: PM=進行管理ネタ、リサーチ=情報収集ネタ、ディレクター=構成迷いネタ、
    制作=締切ネタ、目利き=厳しめチェックネタ、配信=投稿ボタン緊張ネタ)
- 表示条件: 対象社員が**作業中**(`state.active`が true かつ`event`が`blocked`/`done`ではない)、
  かつ**実際のイベントメッセージの吹き出しが表示されていない間**、
  6〜9秒程度のランダムな間隔で、ランダムに選んだ小ネタを吹き出しで表示する(表示時間は約3秒)
- 実際のイベントメッセージ(依頼内容・差し戻し理由など)は常に優先する。
  面白いセリフの表示中に実イベントが届いた場合は、即座に実メッセージの吹き出しに差し替える
- 見分けがつくよう、面白いセリフの吹き出しは実メッセージ(白背景)と異なる背景色
  (薄いクリーム/黄系)にする

### 実装への影響ファイル

- `viewer/src/scene/Avatar.tsx`(吹き出しサイズの動的計算、面白いセリフのタイマー処理・表示切り替え)
- `viewer/src/data/flavorLines.ts`(新設)

## 動作確認方法

既存の`scripts/emit-event.mjs`で疑似イベントを`logs/events.jsonl`に追記して確認する
(viewer/README.mdの手順を踏襲)。特に以下を確認する。

- 一度もイベントが無い社員 → 机だけ表示されること
- `start`等の最初のイベントで、左右いずれかから歩いて出社してくること
- `done`イベントで、出社時と同じ側へ歩いて退社し、机だけになること
- ページを開いた直後(過去ログ一括反映時)は出社/退社アニメーションが再生されず、
  最終状態がそのまま表示されること
- 長いメッセージでも吹き出しからテキストがはみ出さないこと
- 作業中、実イベントの合間に「面白いセリフ」がランダムに表示され、
  実イベントが届くと即座に切り替わること
- アクティビティログの文字列が省略されず折り返し表示されること
- 凡例パネルが画面から消えていること

- 社長からClaude Code(またはCodex)へ指示を送れる入力欄(要望8、別途設計。
  現状のviewerは`logs/events.jsonl`を読むだけの一方向の仕組みであり、
  双方向連携には実現方式からの検討が必要)
